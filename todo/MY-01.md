### Acceptance criteria

- [x] The tree matches the structure above; no schema level.
- [x] Lazy loading, loading and empty states, as in PG-02.
- [x] Every node opens an info view (CORE-01).
- [x] Functions are included alongside Procedures (the TODO lists only
      Procedures — confirm intent; MySQL has both stored procedures and stored
      functions).
- [x] System databases (`information_schema`, `performance_schema`, `mysql`,
      `sys`) are dimmed, consistent with PG-03.
- [x] Verified against MySQL and MariaDB if both are supported.

### Notes

- Functions do belong beside Procedures: MySQL has both kinds of stored
  routine, and `information_schema.routines` tells them apart, so the
  database level shows two folders and a routine appears in one of
  them. `Connector.list_routines(kind)` is the one new adapter call;
  an engine that cannot tell them apart answers with every routine, so
  nothing else changed.
- No MariaDB in the test matrix (docker-compose.yml starts MySQL 5.7
  and 8.0), so "verified against MariaDB" is unverified rather than
  done. Nothing in the tree is version- or fork-specific: the folders
  come from capability flags and every catalog call goes through
  `_safe`, which is what keeps 5.7 (no roles) a shorter listing rather
  than an error.
