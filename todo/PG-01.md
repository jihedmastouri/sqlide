## PG-01 — Schema as a first-class level in the object model

- **Status:** done
- **Depends on:** CORE-02
- **Blocks:** PG-02, PG-04, PG-05

### Problem

Postgres is `server/cluster → database → schema → table`; MySQL and SQLite are
not. The app currently flattens this, which is wrong everywhere it appears.

### Acceptance criteria

- [x] The Postgres provider reports schema as a level and objects are addressed
      as `database.schema.object`.
- [x] The sidebar nests tables/views/functions/etc. under their schema.
- [x] The query console has a schema context alongside the database context;
      switching it issues the right `SET search_path` / affects the effective
      search path, and the current search path is visible.
- [x] Object names are qualified in generated SQL, DDL, tab titles and
      breadcrumbs, and are quoted correctly for case-sensitive/reserved names.
- [x] Cross-schema references (a FK to another schema) display fully qualified
      and are navigable.
- [x] MySQL and SQLite views are unchanged — no phantom schema level.
