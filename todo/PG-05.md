## PG-05 — Extension-aware handling and per-extension UI

- **Status:** todo
- **Depends on:** PG-01

### Goal

Popular extensions change what a database *is*. Detect them and adapt.

### Acceptance criteria

- [ ] The Extensions node lists installed extensions with version, schema and
      whether a newer version is available.
- [ ] Available-but-not-installed extensions are listed separately.
- [ ] Install/update/drop actions with a confirmation showing the SQL, gated on
      privileges.
- [ ] A registry maps known extensions to behaviour, starting with: **PostGIS**
      (hands off to PG-04), **pg_stat_statements** (feeds CORE-15), **TimescaleDB**
      (hypertables and chunks in the tree), **pgvector** (vector column display),
      **pg_cron** (job list), **uuid-ossp**/**hstore**/**citext** (type-aware
      display only).
- [ ] Extension-owned objects are attributed to their extension in info views
      rather than appearing as mysterious user objects.
- [ ] Unknown extensions get the generic listing — no errors, no special-casing
      required to function.

### Note

Scope this down at implementation time if it's too big; the registry plus the
Extensions node is the minimum viable slice, the per-extension UIs can each
become their own follow-up ticket.
