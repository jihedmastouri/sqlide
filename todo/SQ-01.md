## SQ-01 — SQLite sidebar tree: full node set

- **Status:** todo
- **Depends on:** CORE-01, CORE-02

### Target tree

```
Connection
├── Tables
│   ├── Columns
│   ├── Keys
│   ├── Foreign Keys
│   ├── Constraints
│   ├── Indexes
│   ├── References
│   └── Triggers
├── Views
├── Indexes
├── Functions
├── Sequences
├── Table Triggers
└── Data Types
```

### Acceptance criteria

- [ ] The tree matches the structure above; no database or schema level for the
      main database (but `ATTACH`ed databases, if supported, appear as siblings).
- [ ] Every node opens an info view (CORE-01).
- [ ] SQLite realities are handled honestly rather than faked: "Sequences" means
      `sqlite_sequence` for AUTOINCREMENT tables and is empty/hidden when absent;
      "Functions" lists built-in and registered functions and is clearly marked
      read-only; "Data Types" reflects storage classes and type affinity, not a
      user-defined type catalog.
- [ ] Internal `sqlite_*` objects are dimmed, consistent with PG-03.
- [ ] Both "Indexes" under a table and the top-level "Indexes" node work, without
      duplicating implementation.

### Note

Confirm the intended meaning of "Functions", "Sequences" and "Data Types" here —
these map awkwardly onto SQLite and may be better dropped than half-implemented.
